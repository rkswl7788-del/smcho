# 개발 계획 — 현장별 공정·기성 대시보드

## 한눈에 보기

1. EPIC 3개, Story 11개로 나누고, EPIC 하나씩 만든 뒤 자동 검사와 화면 확인을 합니다.
2. EPIC 1은 자료 가져오기·필터·현황·추이, EPIC 2는 점검 현장·기록 펼침·CSV, EPIC 3은 근거를 보여 주는 AI 질의와 로컬 전체 검증입니다.
3. 각 Story에는 브라우저에서 해 볼 행동과 화면에 보여야 할 결과를 적었습니다. 터미널·코드·개발자 도구는 보지 않아도 됩니다.
4. 사용자가 확인했다고 답하기 전에는 완료로 표시하지 않습니다.
5. GitHub 저장과 Vercel 배포는 Story에 넣지 않았고, 각각 사용자가 별도로 요청한 뒤에만 진행합니다.

> 교육용 가상 자료 기준입니다. 기준 숫자는 `실습조건.md`의 "정답 숫자"와 `data/검산표.md`입니다.

## 3. EPIC별 진행 방법

| 순서 | 할 일 |
|---|---|
| ① | EPIC 하나를 만듭니다. 여러 EPIC을 한 번에 완료로 처리하지 않습니다. |
| ② | 자동 검사(Vitest)를 실행하고 결과를 보고합니다. |
| ③ | 브라우저를 열고, 사용자가 확인할 행동과 보여야 할 결과를 하나씩 알려 드립니다. |
| ④ | 사용자가 확인했다고 답하면 완료로 표시하고 `docs/05_테스트결과.md`에 기록합니다. |
| ⑤ | 계산 정확성·오류 처리·자동 검사는 빼지 않습니다. 화면만 있고 동작하지 않는 상태로 완료 처리하지 않습니다. |

## 4. 사용자가 별도로 요청한 뒤 진행하는 단계 (Story 아님)

| 단계 | 시작 조건 | 비고 |
|---|---|---|
| GitHub 저장 | 사용자가 저장소 주소를 알려 주고 "이 저장소에 올려 줘"라고 요청할 때만 | 저장소 생성·커밋·푸시는 요청 전에는 실행하지 않습니다. `.env.local`은 올리지 않습니다. 저장이 끝나면 보고하고 멈춥니다. |
| Vercel 배포 | 사용자가 배포할 프로젝트·저장소를 정해 별도로 요청할 때만(STEP 11) | 프로젝트 생성·저장소 연결·환경 변수 등록·배포, GitHub 연동 자동 배포 설정은 요청 전에는 하지 않습니다. GitHub 저장 요청은 배포 요청을 포함하지 않습니다. |
